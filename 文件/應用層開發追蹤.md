## 0. 三個決定整個設計的前提（2026-09-08 盤點程式碼後確認）

### 0.1 「不重跑策略」要拆成兩件事

| | 要不要跑 | 依據 |
|---|---|---|
| 15,810 個策略的全域掃描回測（Phase 1-4 sweep）| ❌ **不用** | 凍結在 `_frozen/stage0/candidate_index.parquet` |
| 被選中那 ~30 檔策略「**現在**會買哪些股票」| ✅ **必須跑** | 財報更新 → 同一策略定義選出的股票就變了 |

第二件事**目前沒有現成介面**，但底層機械齊全：
`fcv_core.MarketData.get_mask()` 能算出條件當下有哪些股票通過，
`candidate_index` 有 `F1_factor/F1_band/F2_*/C_id/C_source/C_rule/V` 可還原策略定義。
⇒ **要新寫的是一層薄包裝（策略 uid → 當期持股清單），不是重跑回測。**

### 0.2 Fund house 的「兩個時鐘」，我們的研究結果剛好對得上

```
快時鐘（每季 · 財報更新驅動）
  └→ 策略組合不變，重新執行選股 → 換股（rebalance）
      對應 fund house 的「投組再平衡」

慢時鐘（每 2 年 · OOS 窗到期驅動）
  └→ 重跑 HRP 分群 + 重選策略組合 → 換策略（re-selection）
      對應 fund house 的「策略檢視 / 經理人汰換」
```

🔴 **慢時鐘的 2 年不是隨便訂的**——正好是 H-26 實測出的最佳窗口設定
（IS72/OOS24，OOS 每 2 年一段）。**研究結果直接變成系統的運作參數**，
這一段本身就是論文素材。

### 0.3 AI 層必須沿用既有的抗幻覺鐵則

專案已有兩個做完的 LLM 解釋模組，都用同一套架構：
`code/research/cluster_story.py`（群間互補解釋）、
`code/research/cluster_identity.py`（單群身份解釋，H-08）。

> 鐵則（`cluster_story.py` docstring 原文）：**互補程度由程式判定，LLM 只為既定判決寫字**

⚠️ **新的 AI 層必須沿用**，否則會毀掉論文最重要的方法論貢獻（S-08 抗幻覺架構）。
實作上：程式先算出判決（這期選了什麼、跟上期差在哪、風險集中在哪、歷史類似情境）
→ LLM 只把**已算好的判決**寫成人話，禁止推論程式沒算的東西。

## 1. 五層架構

```
┌─ L4 · UI 層
│   設定與執行 / 本期持倉 / 風險儀表板 / AI 解讀 / 歷史版本比較
├─ L3 · AI 解釋層（沿用 §0.3 鐵則）
│   程式算判決 → LLM 寫成「投資委員會備忘錄（IC memo）」風格
├─ L2 · 風控層 ← 🔴 直接回應老師 9-8 的 fund house 風控意見
│   單群上限 / 單標的上限 / 市場配置 / backfill 警示
├─ L1 · 執行引擎
│   讀設定 → 跑下游管線 → 當期持股 + 績效/風險數字 + 決策軌跡
└─ L0 · 設定層（RunConfig：可存、可重用、可版本比較）
     市場 / 精選比例 / 分配方式 / 群數來源 / 風控上限 / 兩個時鐘的頻率
```

### 現有資產 vs 要新寫的

| 層 | 已有（可直接接）| 要新寫 |
|---|---|---|
| **L0** | `code/research/contracts.py` 的 schema 慣例 | RunConfig 定義與存檔 |
| **L1** | `research.cli`（一行指令跑一階段）、`cluster_representatives.select_representatives`、`four_group_control` 的組合評估、`freeze` manifest 鏈 | **策略 uid → 當期持股**包裝、orchestration 膠水 |
| **L2** | `four_group_control` 已有 `max_cluster_share` / `n_clusters_covered` 診斷欄位 | 風控門檻判定 + 違規攔截 |
| **L3** | `cluster_story` / `cluster_identity` 的架構、`utils/openai_quota` 額度煞車 | 新的判決計算 + IC memo prompt |
| **L4** | 無（環境未安裝任何 UI 套件，已確認）| 整個 UI app |

## 5. 設計原則備忘（開發時要守住的）

1. **抗幻覺鐵則不可破**（§0.3）——程式判定、LLM 只寫字
2. **不碰凍結鏈**——L1 的重跑是讀凍結產物 + 算當期持股，不改 `_frozen/`
3. **可追溯**——每次執行都要留決策軌跡（沿用 `freeze` manifest 的精神），
   對應 fund house 的 audit trail
4. **風控要能擋，不能只標記**——老師的台積電集中度問題是實務要求，不是報表欄位
5. **設定可重現**——同一份 RunConfig 重跑要得到同樣結果（除非資料更新了）
