## 0. 一分鐘總覽（最重要，先讀這個）

**論文主軸**：把 AQR 這間量化投資公司**原本人工的投資流程 Agent 化**，用 LLM Agent 去跑原本靠人的環節。

**清大 vs AQR 的關係（易誤會，務必記住）**：
- **清大永續基金 = 起點／靈感來源**，不是主軸。它只是最初參考的對象。
- **AQR = 真正的主軸與研究對象**。
- **為什麼轉向**：清大基金有太多「人為決策」節點，要把這些改成 LLM 並論證其可行性太困難；相對地，AQR 本來就是高度系統化、規則化的流程，天生好 Agent 化。這個「從清大轉向 AQR」的理由本身是論文的重要敘事。

**Agent 的定位（另一個易誤會點）**：
- **生成因子 → 交給 FCV 工具**（規則化、大量生產），不是用 agent 生成。
- **Agent 負責的是因子生成「之後」的環節**：因果解釋評估、跨市場效能診斷、組合建構與調度（即「怎麼運營一個 Fund House」）。
- Agent 不是外來要「接回」的東西，而是論文第三章要設計的「AQR 流程 Agent 化」架構本身。

**近期在做的事**：把 FCV 這套因子工具，從純台股擴充成**台股 + 美股都能跑**（同一套系統 + market 參數），作為後續 agent 化與跨市場研究的資料/工具基礎。

## 1. 論文定位與核心貢獻

### 研究對象與主軸
- **核心對象**：AQR Capital Management（實務公司，整篇論文根基）。
- **AQR 五步驟流程**（agent 化的對象）：因子研究 → 信號建構 → 組合優化 → 交易成本控制 → 因子監控。
- **AQR 核心哲學**：「因子必須有因果解釋」——這是論文最關鍵的差異化起點，決定了 LLM Agent 在哪些節點不可取代。

### 核心貢獻（LLM Agent 的不可取代節點）
1. **因果解釋評估**：對因子/策略判斷「為什麼有效、有無合理財務邏輯」，而非只看統計績效。這是相對 FactorMAD（純統計驅動）的根本差異。**關鍵**：這必須是「會擋下因子」的決策節點，不是事後貼說明的旁白（呼應 AQR「因子必須有因果解釋」的靈魂）。
2. **跨市場效能診斷**：解釋「為什麼某策略在台股有效、美股無效」。這是有了台美兩市場才做得起來的節點。

### 方向修正的脈絡（Fund House）
- 老師的反思：**重點不是找最強因子（super alpha），而是當 Fund House**——手上有很多支「還不錯」且互補的策略，研究怎麼組合、何時用哪種、各放多少錢。
- 原因：super alpha 幾乎必有嚴重過度配適，學術上難證明；且台股內部高度同漲同跌，需要美股提供分散來源。

## 2. 系統整體架構（分層 + Agent 定位）

```
第一層 資料層（現在在做）
  台股 TEJ + 美股 FMP → 整理成同一套格式  ← 純資料工程，無 agent
        ↓
第二層 策略生成層（FCV 工具，快弄好）
  FCV 條件工廠在台美各自產生一批策略武器  ← 規則化批次運算，無 agent
        ↓
第三層 Agent 的核心價值（論文貢獻）
  ・因果解釋評估（會擋因子的決策節點）
  ・跨市場效能診斷（台美為何有效/無效）
        ↓
第四層 Fund House 組合與調度（老師反思後的新重心）
  ・組合建構、互補性/相關性分析
  ・市場環境判斷（regime）→ 何時用哪種策略、配置多少
  ・可能的 Market Environment Agent / 組合決策 agent
```

**FCV 在 AQR 五步驟裡的位置**：取代「因子研究 / 信號建構」那兩步（原本人工設計因子 → 改用 FCV 規則化生成）。Agent 化重心在第三步（組合優化）之後。

## 3. 近期工作重點：FCV 台美股程式設計與修正

> 這是當前實際在動手的部分。目標：讓 FCV 系統同時支援台股與美股。

### 3.1 架構決策（已定）
- **同一套系統 + market 參數**（非兩套獨立系統），因為 Fund House 要做跨市場組合，需輸出格式一致。
- **接法 A**：FMP → 寫進 MySQL（沿用現有表）→ FCV 照常從 MySQL 讀。台美走同一套 get()。
- **核心原則**：差異收斂在資料層，get() 以上完全共用。

### 3.2 現況（已查證的事實）
- FCV 系統（`stock_factor_lab`）程式碼目前是**純台股**：三查詢寫死 `WHERE exchange_name='TWSE'`、前瞻防護是台股法定公告日規則、大盤基準寫死 taiex、`indicator()` 的 market 參數是註解掉的死碼。
- `lab` 資料庫是**台美並存**：美股約 9451（NASDAQ/NYSE/AMEX）、台股 TWSE 1775 家。
- 美股財報的 `date` 存的是**期末日、非公告日**，庫中**無 filing date**（僅 8 張表）→ 前瞻防護要自己補。
- 舊的美股 collector（`USCollectorFactory`）**設計上存在但檔案不在 repo**（`CollectorFactory.py` 有 import 卻找不到資料夾）→ **決定從台股版 collector 改寫**。
- ✅ 更新(2026-07-03)：已建立自有 collector repo **`Dowgojashan/stock_factor_collector`**（seed 自 TW collector）。美股一律在此用 FMP 重寫 `USCollectorFactory/`，舊 US 碼不沿用。FCV 讀取端 repo 也已轉為自有 `Dowgojashan/stock_factor_lab`。細節與 D1–D11 決策見 `美股接入_開發計畫.md`。

### 3.3 三個技術挑戰與解法
1. **資料格式不同**：FMP JSON vs 系統契約格式（date/company_symbol/factor_name/factor_value）。解法：在 collector 入庫時轉換，格式差異全吸收在「FMP→MySQL」這段，資料庫成為統一交會點。
2. **財報時點對齊（前瞻防護，最關鍵）**：美股會計年度不統一（如蘋果 9 月底），不能套台股月份規則（會把年報誤判成 Q3）。解法：用 FMP 的 `fillingDate`（注意官方拼法兩個 l）逐筆對齊，在 factorvalue 新增 `filing_date` 欄。
3. **三個格式陷阱**：①單位/比例尺（FMP 多小數，須對齊台股範圍）②日期語意（美股走 filing_date，不走月份規則）③公司代號（台股數字 vs 美股英文 ticker，勿觸發數字代號的台股邏輯）。

### 3.4 要改什麼、不動什麼
- **要新增**：FMP 美股 Collector（公司/價量/財報/因子），從台股版 `TWCollectorFactory` 改寫。
- **要修改**：`database.py`（市場查詢）、`format_data.py`（前瞻防護加美股分流）、`get_data.py`（market 參數）、回測費率（美股無證交稅）。
- **不動（共用層）**：`condition_factory.py`、`fcv_experiment_spec.json`、`combinations.py`、`report.py`、`report_analysis.ipynb`。

## 4. 近期行動計畫（兩線並行）

> 策略：台股先跑通當「已知正確的參照組」，同時開始寫美股系統。

### 線 A：台股跑通 + 產出策略工廠（優先）
- **A1 台股資料更新**（進行中）：2023 → 2026。更新後務必抽樣驗證日期、數值、前瞻防護。⏱️ 1–3 天。
- **A2 跑一次完整 FCV 確認 pipeline 沒壞**：先求能跑、結果合理。⏱️ 0.5–1 天。
- **A3 補「自動產生配方」那層**：⚠️ **系統其實已能吃多組配方一起跑（批次回測已有）**，缺的只是「自動枚舉指標×門檻組合、生成 JSON」這一小段。⏱️ 1–3 天。
- **A4 產出台股策略武器庫**：⚠️ **篩選/排名工具已現成**（`report_grouping.py` 的 `select_top_strategies`、熱力圖、分組排名；`stats_test.py` 統計檢定）。直接用，參考 `report_analysis.ipynb`。⏱️ 0.5–1 天 + 機器時間。
- **線 A 小計**：約 1–2.5 週。

### 線 B：美股系統（並行）
- **B1 FMP 串接驗證**：單一公司（如 AAPL）確認欄位齊全、fillingDate 有回傳、單位。⏱️ 1–2 天。
- **B2 資料庫加 filing_date 欄**：台股留空、美股填 fillingDate。⏱️ 0.5 天。
- **B3 從台股版改寫美股 Collector**（工作量最大）：US 版 Company/Stock/Indicator/Factor Collector；資料來源改 FMP、欄位對應（用 singleindicator 的 us_indicator）、單位對齊、filing_date 寫入；產業分類先跳過。⏱️ 1.5–3 週。
- **B4 改 FCV 讀取層支援 market**：database 查詢、前瞻防護分流、get_data market 參數、費率。小心別弄壞台股，每次改完跑台股回歸測試。⏱️ 3–5 天。
- **B5 美股單因子 MVP**：小範圍（S&P500 或 country='US'）跑通 ROE 單因子，重點驗證無前瞻偏誤、跟台股量級對照。⏱️ 2–4 天。
- **線 B 小計**：約 4–7 週（B3 是主要變數）。

### 並行安排
- 第 1–2 週：線 A 全力推 + 穿插 B1、B2。
- 第 2–3 週：線 A 收尾（產出台股策略武器庫）+ 線 B 開始 B3。
- 第 5–7 週：B4 + B5，跑出第一個美股 MVP。
- **之後**：兩市場都有策略 → 進入第三、四層（agent 化、Fund House 組合）。

## 6. 待釐清 / 待討論（agent 細節，後續再深入）

以下 agent 設計細節，等台美工具跑通、有實際策略與回測結果後再討論：
1. **跨市場比較 Agent 的交接點**：台美 FCV 工具的產出，怎麼餵給跨市場診斷 agent？資料工程與 agent 的界面在哪。
2. **因果解釋如何驗證**：質性輸出（解釋對不對）怎麼證明不是 LLM 幻覺？可考慮情境驗證（橋水四象限）、專家評分、或「採納 vs 不採納」的績效反證。
3. **解釋 agent 的決策性**：確認實作時因果評估是「會擋下因子」的節點，而非事後旁白。
4. **市場範圍定義**：美股用 exchange（所有在美掛牌）或 country='US'（僅美國本土，約差 1500 家）。MVP 先用 S&P500。
5. **時間分配提醒**：資料工程是手段、agent 化才是論文核心貢獻。避免 FCV 台美做太久排擠 agent 設計時間（老師：每部分 70 分即可、抓一個 focus）。

## 7. 品質紅線（進行中務必守住）

- **前瞻偏誤是紅線**：美股 MVP 一定要驗證有用 filing date 對齊。
- **每次資料更新後抽樣驗證**：日期、數值、前瞻防護，別更新完就假設對了。
- **美股務必跟台股對照**：同因子（如 ROE）數值量級應在合理可比範圍，差很多就是單位沒對齊。
- **改讀取層時保護台股**：每次改完跑台股回歸測試，別為美股弄壞台股這條乾淨對照組。
- **倖存者偏誤**：確認 FMP 美股清單是否含已下市公司。
- **樣本內/外切分**：跑策略工廠時確認有做，關乎選出策略可信度。
