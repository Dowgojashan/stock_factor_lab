## 0.5 分階段設計：一次只開一個構面

一個「策略」＝ `F1 × F2 × C × V` 四個構面的組合，策略數是**連乘**出來的。
本計畫刻意讓四個構面**一次只開一個**，上一階段淘汰的因子不帶進下一階段：

| 階段 | F1 | F2 | C | V | 策略數（台股） |
|---|---|---|---|---|---|
| **Phase 1** | 9 桶 | ❌ 關 | ❌ 關 | ❌ 關 | **180** |
| Phase 2 | 3 桶（過關者） | ✅ 開 | ❌ 關 | ❌ 關 | 數百 |
| Phase 3 | 同上 | ✅ | ✅ 開 | ❌ 關 | 數千 |
| Phase 4 | 同上 | ✅ | ✅ | ✅ 開 | ×2 |

**為什麼這樣做**：要判斷「這個因子自己有沒有訊號」，就不能讓其他構面幫忙。
Phase 1 便宜不是偷工減料，而是它問的是一個更單純的問題。

實作：`fcv_core.py` 於 2026-08-07 新增 `stream_strategy_masks(..., v_modes=)` /
`run_spec(..., v_modes=)` 參數（純新增，預設 `("v0","v1")` ＝加入前行為完全相同）。
Phase 1 傳 `("v0",)`。

## 1. 架構的根本改變：批次結構會消失

這是整個計畫最重要的一點，先講清楚。

### 現行架構（要被取代）

```
每批 = 固定{ROE, EPS, FCF_P} + 1個候選因子
10個候選 → 10批 → 每批 7,140 策略 → 共 67,435
```

**問題**：「ROE/EPS/FCF_P 固定」這個前提**從來沒被驗證過**。老師甚至直接質疑其中的 ROE：

> 「ROE 的區隔有點怪…反而是 ROE 小的其實是比較賺錢的」

而且這個結構有大量浪費：每批都含 3,780 個「只用固定三因子」的策略，
**10 批重複回測了 37,800 次同樣的東西**。

### 新架構（老師的方法）

```
所有因子平等 → 線性檢定篩掉不合格的 → 通過的才配對 → 才測C
```

沒有「固定因子」、沒有「候選因子」、沒有「批」。ROE 如果過不了線性檢定，它就跟 MOM 一樣被淘汰。

**規模反而變小**（詳見 §6），因為消除了重複。

## 2. Phase 1：9桶單因子線性檢定

### 2.1 目的

回答老師的第一個問題：**「這個因子到底有沒有訊號？」**

> 「第一個通常會先判斷**有沒有線性**…有線性的才拿出來，**沒有線性表示這個因子不行**」

### 2.2 實作方式（不需改引擎）

利用引擎既有邏輯「同因子的桶不互相配對」：
- 每個因子跑一份獨立 spec，`P1` 只放該因子的 9 個 `q_band`
- `P3 = {}`（空）→ 只會產生 `C=None`
- 自動得到「純單因子」結果

```
label  : TW_L1_{因子}_M
P1     : {因子: [q_band(k,9) for k in 0..8]}
P3     : {}            → 只有 C=None
v_modes: ("v0",)       → V 也關掉
產出   : 9桶 × 1(None) × 1(v0) = 9 策略/因子
```

20 個因子 → **180 個策略**

> ⚠️ **已知前瞻偏誤：MOM1 不列入評選**（`phase1_linearity.LOOKAHEAD_FLAGGED`）。
> MOM1 =(公告日+45天收盤 − 期末日收盤)/期末日收盤，但
> `format_data.py::adjust_index_of_report` 讓財報在**公告日當天**就可用
> → 選股依據已含未來 28~45 天的股價。ρ=1.000、桶0 −22%→桶8 +68%（跨度 90pp、
> 且是唯一有負值桶的因子）就是偷看答案的特徵。
> 仍照跑照畫圖並標記 `🚫 前瞻偏誤`，供報告說明用。
> 要真正救回需回 collector 改成「往前推」的定義。**MOM 本身乾淨、無此問題。**

### 2.3 檢定內容

對每個因子的 9 個桶（用 v0、CAGR 中位數）：

| 檢定 | 方法 | 用途 |
|---|---|---|
| **單調性** | Spearman ρ（桶序 vs CAGR） | 主判準 |
| **顯著性** | ρ 的 p 值 | 排除巧合 |
| **形狀分類** | 單調↑ / 單調↓ / 倒U / U型 / 無序 | 決定該因子怎麼用 |
| **極端桶效應** | 桶0、桶8 vs 中間7桶 | 判斷是否只有極端端有效（MOM 型） |
| **樣本充足性** | 每桶策略的平均選股數 | 桶太細會選不到股 |

### 2.4 判定規則（草案，數字待討論）

| ρ | 判定 | 後續處理 |
|---|---|---|
| \|ρ\| ≥ 0.85 且 p < 0.05 | **✅ 過關** | 湊回 3 桶，進 Phase 2 |
| 0.5 ≤ \|ρ\| < 0.85 | ⚠️ 邊際 | 看形狀：倒U/U 型另案處理 |
| \|ρ\| < 0.5 | ❌ 淘汰 | 除非極端桶效應顯著（MOM 型） |

**特例：MOM 型因子。** 老師明說動量因子只有最強那一端有意義：

> 「MOM 的話越強的就是越 OK…**你不會那麼傻去選 MOM(的中後段)**，你一定是只想找最厲害的」
> 「你的股票夠多…所以你幾乎是可以抓**前 10~20 分位**」

所以對 ρ 不顯著但**桶8（或桶0）單獨顯著優於其餘**的因子，
改用「只取極端桶」而非「切3桶」進入 Phase 2。這是有依據的處理，不是特例放水。

### 2.5 ✅ 執行結果（2026-08-07，台股）

### 2.7 成本 —— 為什麼這麼快？（資料期間完全沒有縮水）

**Phase 1 跑的是完整 2000–2026 全期間，一天都沒少。**
快的原因不是資料變少，而是**要跑的策略組合少了 25 倍**：

| | 資料期間 | 策略數 | 時間 |
|---|---|---|---|
| 現行一批 | 2000–2026（全） | 7,140 | ~2 小時 |
| **Phase 1** | **2000–2026（完全相同）** | **288** | **~7 分鐘** |

實測依據（美股 EV_EBITDA 批的 log）：
```
資料載入        = 162 秒     ← 固定成本，與策略數無關
回測 7,140 策略 = 7,018 秒   → 每策略約 0.98 秒（每一秒都在跑完整 26 年日頻回測）

Phase 1 = 162 + 288 × 0.98 ≈ 7.4 分鐘
```

策略數的來源差異：
```
現行一批 = 170 個F組合 × 21 個C狀態 × 2 個V = 7,140
Phase 1  =  16 因子 × 9 桶 × 1(無C)  × 2 個V =   288
```

Phase 1 只有 288 是因為它**刻意不配 F2、不套 C**——老師的方法就是先單獨看每個因子
自己有沒有訊號，把變因降到最少。Phase 2 開始配 F2、Phase 3 加 C 後，
策略數會回到萬級、時間回到小時級（見 §6）。

## 3. Phase 2：湊回 3 桶 + 不對稱 F1×F2 配對

### 3.1 為什麼要湊回 3 桶

> 「所以我們只切 3 個區間，**因為這樣子樣本才夠大**」
> 「9 要拼回 3 OK 啊」

9 桶用於**判斷形狀**（點多才看得準），3 桶用於**實際跑策略**（每桶樣本夠大才穩）。

### 3.2 ⚠️ 與老師的一個技術分歧

老師認為湊回 3 桶不用重跑：

> 「我再把它拼回，**我就不用重算啊**…算數湊回來而已啊」

**這對統計量成立，對回測不成立。** 把桶0/1/2 合併成「前 33%」，選股清單就變了
（從三個各 11% 的獨立投組，變成一個 33% 的投組），持股數、權重、交易成本全都不同，
**必須實際重跑**。

處理方式：照重跑執行，並準備一份對照說明（9桶算數合併 vs 3桶實跑的差異），
下次開會可以直接跟老師報告這個發現——這本身也是方法論上的一個小貢獻。

### 3.3 不對稱配對（老師的核心設計）

> 「你一個把它定成 **primary**，一個是 **secondary**」
> 「primary 一定要是…有意義的。secondary 就是要符合某些[寬鬆條件]」
> 「至少跟大盤差不多，或者說是輸大盤不多」
> 「**primary 本身就已經很強了**，或 primary 加上某一點點比較寬鬆的 secondary 夠強了，
> 這時候我就可以把它**晉升**」
> 「F2 **可以是空集合**」

| 角色 | 門檻 | 意義 |
|---|---|---|
| **F1 (primary)** | 嚴格：Phase 1 過關 **且** 單獨跑就要顯著贏大盤 | 主訊號 |
| **F2 (secondary)** | 寬鬆：「至少跟大盤差不多，或輸大盤不多」 | 輔助/不拖累即可 |
| **F2 = 空集合** | 允許 | primary 夠強就不需要 F2 |

### 3.4 實作要點

- 回測層仍用 `dedup=True`（A∩B 與 B∩A 遮罩相同，跑兩次是浪費）
- **角色標記在分析層**：同一個策略可同時是「A為primary」與「B為primary」兩種解讀，
  在 stats 上加 `primary_factor` / `secondary_factor` 欄位分別評估
- 產出：**「固定的體質檢查表」**——一組通過門檻的 F1(×F2) 組合

### 3.5 這一關的產出

一張明確的表：哪些 F 組合有資格進入 C 測試。
老師期待的規模：

> 「大概從這 20 幾個，我大概可以**區隔出其中的 3 到 5 個是比較優的**」

## 4. Phase 3：C 構面測試

### 4.1 順序不能顛倒

> 「OK 了以後，我就直接去檢查 C」

F 定案後才碰 C。這是為了避免「同時挑 F 和 C」造成的雙重選擇偏誤
（老師說的「**如果三個因子都作弊，應該會有不少快 40**」）。

### 4.2 老師點名要補的兩件事

**(a) C 之間的相似性**
> 「A.I.C 互補性…稍微比較講一下，**是不是不太像**（是不是太像了）」

要做：20 個 C 的**相關矩陣**（用各 C 的選股遮罩重疊率或策略 CAGR 相關）。
預期發現：C3(ROE近4季最高) 與 C4(ROE近8季最高) 本質只差回看窗，
C10/C11 同理——**20 個 C 的真實自由度可能只有 6~8 個**。

**(b) 自創 C 的正當性**
> 「應該 C1 到 C8 是原本學姊的…**你自己瞎掰出來的 C**，要不要以後給分啊」

C1~C8 有論文依據，C9~C20 是我們擴充的，需要補上設計理由。
老師同時給了正面方向：

> 「它可能已經有找到**新的 pattern，新的 C**」
> 「你要搞出一個新的啊，你要搞出一個很**台**的啊」

→ 把「自創」從缺點轉成貢獻：找出**適合台股的新 C 條件**。

### 4.3 兩個獨立的約束條件（目前完全沒做）

> 「這個剩下的**不可以太少**…不然後面就沒有 LLM 的必要」
> 「但是裡面**被選出來的[股票]不能太少**，那就是策略不[穩定]」
> 「所以他的**限制是不一樣的**」

| 約束 | 對象 | 現況 | 要補 |
|---|---|---|---|
| 策略數夠多 | 整個池 | ✅ 有（但太多，28,970 個） | 反向收緊 |
| **每策略選股數夠多** | 單一策略 | ❌ **完全沒檢查** | **新增** |

現行 `MIN_TRADES=5` 檢查的是**交易次數**，不是**同時持股數**。
集中度分析已發現 EV_S 冠軍**平均每月只持 3.5 檔**——正好踩在老師說的紅線上。

**已定案：`MIN_HOLDINGS = 10`（平均每月持股數）**，從 `position.parquet` 計算，
在**分析層**執行（不寫進回測層，理由見 §8）。
影響預估：現行三個冠軍中 EV_S(3.5檔) 會被剔除，PB(10.5)、P_IC(11.6) 勉強保留。

> 你再去分析他的實際的獲利風險 profile…**什麼時候賺錢、什麼時候賠錢**」

> 「你**不可以用太多資料**…你分析過去的那個模型，跟分析未來的那個模型，**要一樣**」

本計畫先做到 Phase 3，Phase 4 待前三關穩定後另行規劃。

### 決議 2 的連帶影響（要有心理準備）

若 ROE 沒通過線性檢定：
- 現行 10 批的「固定三因子」前提就**確定失效**，那 67,435 個策略的結果只能當探索紀錄，不能寫進論文結論
- 但這**正是老師要的答案**——證明我們的 SOP 有能力淘汰不合格的因子，
  而不是「不管好壞都硬套」。這是方法論的說服力來源，不是壞消息

### 決議 4 的連帶影響

`MIN_HOLDINGS = 10` 這個過濾會在**分析層**執行（從 `position.parquet` 算平均每月持股數），
**不寫進 `fcv_core.py` 的回測層**——理由：
- 回測層加過濾會讓策略在落地前就被丟掉，之後想調門檻就得重跑
- 分析層過濾可以隨時改門檻、也保留「被剔除的策略長什麼樣」供檢查
