## 5. 這次踩過的坑（重複踩會浪費很多時間）

1. **T8 不能拿來算群佔比**（2026-09-09 實跑抓到，差 2.8~3.6 倍）
   `ops.tools.t8_compute_portfolio_risk` 的 `cluster_coverage` 對到的是**凍結的全域六棵樹**（固定 k），
   但 walk-forward 每一窗自己重建的樹（`k_mode="silhouette_is"`）群數完全不同，兩者對不起來。
   → 群佔比要讀 `engine.Holdings.cluster_info`（該窗自己算好、已凍結的正確數字）。
   T8 只能用來算**跟分群無關**的 `portfolio_mdd`／`portfolio_ann_vol`。
   ⚠️ 這個教訓對未來的 `live` 模式同樣成立（T9 重建的新樹也不在 `cluster_assign.parquet` 裡）。

2. **anchored 不要改成 rolling**——H-26 已實測 rolling 是 13 個方案裡**最差**的
   （OOS CAGR 20.95% vs anchored 22.44%）。曾有外部審查建議改成「往前抓 72 個月」，那就是 rolling，已明確排除。

3. **測試 130/131 不一定是程式壞了**——唯一會掛的 `t_ops_t11_regime_label_valid` 需要即時資料庫，
   資料庫沒開就會失敗，其餘 130 項都吃凍結資料。

4. **文件路徑會過期**——2026-09-09 全面查證發現 CLAUDE.md 有 9 個指向不存在檔案的死連結
   （包括它自稱「最重要」的那份）。**改檔名/搬檔案後記得回頭更新引用**，
   也因此本次把 `老師9-8意見待報告事項_2026-09-15.md` 改名為 `_下次會議10-01.md`（日期式檔名容易誤導）。

## 6. 應用層速查（新加的部分，其他文件還沒完整涵蓋）

```bash
cd code                                   # 一定要在 code/ 底下跑（config.ini 是相對路徑）

# CLI
python -m app.cli new-config my_run.json --market TW --scheme A --window-no 6
python -m app.cli run my_run.json                    # 會寫稽核紀錄
python -m app.cli run my_run.json --no-record        # 只看數字，不留紀錄
python -m app.cli run my_run.json --memo             # 加 AI 備忘錄（dry-run，不花錢）
python -m app.cli run my_run.json --memo --live-llm --llm-purpose cluster_story
                                                     # 真的呼叫 LLM（借用 cluster_story 的 gpt-5，
                                                     # 因為 config.ini 還沒設 app_memo_model）
# UI
streamlit run app/ui.py
```

五層架構：`config.py`(L0) → `engine.py`(L1) → `risk.py`／`calibration.py`(L2) →
`memo.py`(L3) → `cli.py`／`ui.py`(L4)，`audit.py` 記錄每次執行。
決定事項與門檻依據全部在 `應用層開發追蹤.md`。
