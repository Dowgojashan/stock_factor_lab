`memo.py`(L3) → `cli.py`／`ui.py`(L4)，`audit.py` 記錄每次執行。
決定事項與門檻依據全部在 `應用層開發追蹤.md`。

## 7. 可用的 skills（`.claude/skills/`，2026-09-09 建立）

用 `/<名稱>` 呼叫。這些把使用者最常重複的研究流程固化下來，**內容是本專案特化的**
（含真的踩過的坑），不是通用模板。

| Skill | 什麼時候用 |
|---|---|
| `meeting-digest` | **開完會後**：逐字稿 → 分類成必做/取消/待確認/感想 → 更新文件。🔴 含「檢查推翻了哪些既有共識」那步 |
| `meeting-prep` | **開會前**：盤點進度 → 挑報告內容（結果導向）→ 排順序 → 列出要老師拍板的事 |
| `meeting-followup` | **開會前**：稽核有沒有默默漏掉的交辦、文件有沒有跟著更新、數字有沒有過期 |
| `methodology-review` | **報給老師/寫進論文前**：前視偏誤、倖存者偏誤、資料窺探、對照組公平性、靜默資料錯誤。附 `pitfalls.md` 八類本專案實際踩過的陷阱 |
| `decision-log` | **拍板一個設計選擇後**：記錄依據的數字、排除了什麼、為什麼排除、何時要重新檢視 |
