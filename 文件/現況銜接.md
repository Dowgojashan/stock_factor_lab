## 5. 這次踩過的坑（重複踩會浪費很多時間）

1. **T8 不能拿來算群佔比**（2026-09-09 實跑抓到，差 2.8~3.6 倍）
   `ops.tools.t8_compute_portfolio_risk` 的 `cluster_coverage` 對到的是**凍結的全域六棵樹**（固定 k），
   但 walk-forward 每一窗自己重建的樹（`k_mode="silhouette_is"`）群數完全不同，兩者對不起來。
   → 群佔比要讀 `engine.Holdings.cluster_info`（該窗自己算好、已凍結的正確數字）。
   T8 只能用來算**跟分群無關**的 `portfolio_mdd`／`portfolio_ann_vol`。
   ⚠️ 這個教訓對未來的 `live` 模式同樣成立（T9 重建的新樹也不在 `cluster_assign.parquet` 裡）。

    `artifacts_dir` 欄 **100%** 是 `D:\git\stock_factor_lab\code\results_artifacts\...`，
    那是舊機器的路徑。加上本機 `code/results_artifacts/` 只有 3 個 spec 目錄
    （**189GB 的逐策略回測產物換機器時沒複製過來**），所以
    `t_stage0_artifacts_exist`（讀凍結欄位）跟 `t_stage0_idempotent`（重算新機器路徑）
    兩項都會掛，這就是本機 129/131 的原因。
    ✅ **影響範圍僅限「重跑 stage0」**——stage0 產物已凍結，下游全讀 `_frozen/`，
    **應用層完全不受影響**（實測 `app.cli`／`app.clustering` 正常、G4 驗收 14/14）。
    ⚠️ 要重跑 stage0 才需要處理：從舊機器複製 `results_artifacts/`，
    或改成存相對路徑（`artifacts_dir` 存絕對路徑本身就是可攜性缺陷）。

12. **快時鐘的「今天」其實不是今天**——三層截斷：①台股財報套法定公告期限
   （`format_data.py:158`，Q2 要 8/31 才生效）②財報 frame 被 `price_index.max()` 截掉
   （`fcv_core.py:196`）③`resolve_holdings` 取 ≤ 指定日的最近交易日。
   2026-09-10 實測結果：UI 點「今天」實際落在 **2026-07-24 ＋ 2026Q1 財報**。
   這反而讓橫斷面很乾淨（不完整的 2026Q2 自動被排除），但要知道有這個落差。
   ⚠️ **2026-09-11 更正**：上面的 2026-07-24 只是 **TW** 的最新交易日——**US 股價
   資料庫實際到 2026-08-19**，比 TW 晚約 26 天更新。兩個市場不是同一份「現在」，
   XM 投組會有兩個不同的「今天」（`ui._resolve_stock_holdings()` 現在回傳
   `{市場: 交易日}` dict，不是單一字串，就是為了誠實反映這件事）。

13. **XM 投組的股票解析要分派到兩個 `MarketData`，且兩者交易日曆不同**
    （2026-09-11，S1）：XM 樹的群不是「跨市場分散」的意思，是**群本身就 100% 屬於
    單一市場**（實測群1=100%TW、群2/群3=100%US）；XM legacy 15 檔＝5 TW＋10 US。
    分派依據用 `candidate_index` 的 **`market` 欄位**，不要去解析 `strategy_uid`
    字串前綴（欄位比字串解析更不容易因命名規則變動而壞掉）——見
    `resolve_strategy_holdings.markets_needed()` / `resolve_holdings_multi()`。

14. 🔴 **餵給 LLM 的數字沒統一格式化，D2 會產生假警報**（2026-09-12，`app/explain.py`
    首次正式跑就踩到）：facts 裡只要有任何欄位是未格式化的原始 float（而不是先轉成
    `_pct()`/`_ratio()` 的字串），LLM 有時照抄原始小數、有時「好心」幫你轉成百分比，
    兩種寫法都對但彼此對不上，D2 逐字比對就會誤判成洩漏。**規則：所有要餵進 prompt
    的數字欄位都要先格式化成字串再放進 facts，不能留原始 float 讓 LLM 自己決定怎麼轉。**

15. 🔴 **`_NUMBER_RE` 正則會把範圍/配對記法誤判成負數**（2026-09-12）：舊版
    `r"-?\d+\.?\d*%?"` 碰到「2007-2025」「群3-4」這種文字會把後半段誤判成
    「-2025」「-4」這種不存在的負數。已修成 `r"(?<!\d)-?\d+\.?\d*%?"`
    （負向前瞻斷言：前面是數字就不視為負號）。這是 `memo.py` 共用的正則，
    `explain.py`／`stability.py` 都受惠於這次修正。

16. **D2 逐字比對不能無差別套用在所有結構化欄位上**（2026-09-12，層四 `risk_flags`
    schema 補上後才發現）：`risk_flags[].verification_criterion` 依設計本來就該是
    LLM **自訂**的事後門檻（例如「若回撤超過 5% 則視為應驗」），門檻數字不必是
    facts 裡已存在的數字——對這個子欄位套用「每個數字都要能對回 facts」的規則是
    範疇錯誤（category error），必須排除在掃描之外，只掃 `risk_flags[].risk` 本身。

17. 🔴 **績效衡量的時間窗要跟著快時鐘的重新解析點分段，不能整段算到資料凍結日**
    （2026-09-12，使用者親自抓到，不是我發現的）：`app/performance.py` 算「已實現
    報酬」時，若給定的 `as_of` 到 `end` 橫跨了下一次財報生效日，等於是假裝這批股票
    會被一直持有到 `end`，但實際上快時鐘（B1）會在下一次財報生效日就換股。正確做法
    是把區間切成「`as_of` → 下一次財報生效日」一段一段算，不要一次跳到最後的價格
    凍結日。**UI 上新加的「已實現績效」按鈕目前是單一區間查詢（跟 §9.8 驗證腳本裡
    分段计算的版本不是同一個東西）**，使用時如果 `as_of`／`end` 橫跨了一次以上的
    財報生效日，數字的解讀要留意這個限制。

18. **自動化的「重複穩定度」數字（Jaccard／exact-match）會低估真實穩定度**
    （2026-09-13，S7 層三實測發現）：`stability.py` 量的是「LLM 5 次輸出裡引用的
    數字集合重不重疊」，但當某個欄位本來就有一個很大的歷史資料池可以引用（例如
    `historical_same_setting_windows` 有 40+ 列）時，5 次獨立呼叫各自挑不同幾列
    當佐證例子是正常且合理的行為，卻會被這個指標判定成「不穩定」。**看到低
    Jaccard 分數不能直接下結論，要人工讀過至少一次完整文本，確認是「引用不同但
    同樣有效的例子」還是「核心判斷真的不一致」，兩者天差地遠。**

19. 🔴 **UI 上「查詢已實現報酬」若 `as_of` 晚於價格資料涵蓋範圍會靜默算出誤導性的
    0%**（2026-09-13，`AppTest` 實跑抓到）：`performance.measure()` 內部把
    `as_of`／`end` 都 clip 到各自可得的最後交易日，若使用者選的起算日（例如「今天」）
    已經晚於資料凍結日，clip 後 `as_of` 跟 `end` 會變成同一天，算出「同一天對自己」
    的 0% 報酬，而且不會報錯——使用者很容易誤以為那是真正的量測結果。
    **`app/ui.py` 已在呼叫 `measure()` 之前，自己比對 `md.price_index.max()` 先擋掉
    這種情況並顯示警告**，這個限制是 `performance.py` 本身的行為，往後任何新的
    呼叫端都要記得做同樣的前置檢查，不能假設 `measure()` 會自己報錯。

## 6. 應用層速查（新加的部分，其他文件還沒完整涵蓋）

🔴 **2026-09-10 起有兩種模式**（§7 P2）：
- **正式模式 `--mode live`**：IS＝2007-01~2025-12（228 個月），用 `_frozen/stage3` 凍結
  主線樹**即時挑代表**，**依定義沒有 OOS**。這是「現在該持有什麼」。
- **驗證模式 `--mode replay`**：讀凍結窗次，有真實 OOS。這是「方法在歷史上表現如何」。

⚠️ **正式模式的 `is_cagr` 不是預期報酬**（§8-R13）：歷史上 IS CAGR 中位數比實際 OOS
高 7.62pp（1.48 倍）。UI 已刻意把它從最醒目的 metric 位置移走，改放「同類設定的歷史
OOS 分布」。**不要為了畫面好看把它改回去。**

```bash
cd code                                   # 一定要在 code/ 底下跑（config.ini 是相對路徑）

# CLI
python -m app.cli new-config live.json --mode live --market TW          # 正式模式
python -m app.cli new-config my_run.json --mode replay --scheme A --window-no 6
python -m app.cli run my_run.json                    # 會寫稽核紀錄
python -m app.cli run my_run.json --no-record        # 只看數字，不留紀錄

streamlit run app/ui.py
```
