# S-08：抗幻覺架構方法論（方向D 的交付物）

> **產出日期**：2026-08-31
> **性質**：整理型文件，**沒有新開發**——既有機制已存在於 `cluster_story.py`／`cluster_identity.py`／`decision_layer_arms.py`／`ops/tools.py`，本文件把它們的共同設計原則整理成可寫進論文方法論章節的敘述，並用當下最新資料重跑一次稽核（取代舊的、群數改變前的「84對」數字）。
> **對應論文位置**：貫穿第三章（群的解釋）與第四章（總經→選群），是方向D 的核心貢獻，不獨立成章。

---

## 1. 為什麼需要這套設計

專案裡有四個地方會呼叫 LLM 產生文字（詳見第3節）。LLM 天生的風險是**幻覺**——編造看起來合理但沒有依據的內容。對一個要進論文、要對老師負責的研究系統，這個風險不能靠「事後人工抓錯字」解決，必須是**架構上讓 LLM 沒有機會犯這個錯**。

這句話貫穿整個方向D 的設計，也是本專案在 S-01/S-02/S-03 反覆出現的判斷準則：**不給 LLM 有機會誤用的資訊，而不是事後信任它不會誤用**。

---

## 2. 核心設計哲學：三道鐵則 + 一個總原則

### 三道鐵則（四個LLM節點共用）

1. **程式判決不可推翻**——任何「是非題」（互補程度高中低、四道安檢過不過、規則基準選哪個群）一律由程式算好、凍結，LLM 只負責替這個已經定案的答案寫說明文字，不能自己重新判斷或質疑。
2. **結構化輸出（JSON schema，strict 模式）**——LLM 的回應被限制在固定的欄位結構裡，不能自由發揮出 schema 以外的內容，也讓每個欄位有明確、單一的職責（不能把好幾件事混著講）。
3. **只能引用提供的數字**——側寫資料全部由程式從資料庫算好、餵給 LLM；LLM 不得引用未提供的個股、產業、總體經濟事件，禁止在資料沒給的地方「腦補」因果關係。

### 一個總原則：架構排除，不靠信任

這條是三道鐵則之上更高層的設計判斷，體現在：

- **S-01**：H-08 的四個LLM輸出欄位是同一次呼叫、共用含真實年份的上下文產生的——即使實測沒有外洩年份，那也只是運氣好、不是保證。故決策層介面**只收風險最低的`identity_label`**，其餘欄位一律不用。
- **S-02**：決策層看得到「條件式」績效，看不到「無條件」績效——不是相信LLM不會被無條件的高CAGR誘導去選歷史贏家，而是從一開始就不给它這個誘因。
- **S-03**：決策層 prompt 不含日期——不是要求LLM「不要用它的世界知識」，而是讓它連自己在看哪一段歷史都不知道，記憶用不上力。

## 3. 四個 LLM 節點逐一盤點

| 節點 | 對應開發項 | 產出 | 上線狀態 |
|---|---|---|---|
| T10 | W-05（實戰部工具層） | 把T7的四道安檢判決轉成可讀文字 | ⚠️ **架構已備，尚未上線**——觸發它的Agent1還不存在，目前0筆真實呼叫紀錄 |

| decision_layer_arms（B_llm） | S-05 | 總經狀態下該選哪些群 | ✅ 已上線，靜態快照驗證階段 |

### 3.1 T10（尚未上線）

**設計**：T7 先算好「靠少數股／產業β／規模效應／真alpha」四道安檢的 True/False/None，T10 只負責把這個凍結結果寫成文字。**誠實限制**：產業β這道安檢因為資料庫完全沒有持股逐月產業分類資料，固定回傳None，且明文規定「不可宣稱四道安檢皆通過」——這是資料缺口的誠實揭露，不是隱藏起來。

**現況**：目前 `code/_catalog/llm_usage.jsonl` 裡沒有任何 `t10_return_story` 的呼叫紀錄——它是備好待接的零件，因為觸發它的 Agent1（實戰部）尚未建置。架構驗證只靠合成資料的單元測試，**還沒有真實資料的稽核可以報告**，這一點必須在論文裡如實註明，不能跟其他三個節點混為一談。

### 3.2 cluster_story（H-04，群間互補）

**額外的專屬鐵則**：互補程度「低」時，LLM 必須明講「放在一起不會帶來分散效果」——這是四鐵則之外，針對「LLM可能為了說故事，把明明高度重疊的兩群硬掰成互補」這個具體風險加的規則。

**實證稽核（2026-08-31 重新查證，非舊的84對數字）**：

```
群對總數：39對（TW15+US7×6/2對+XM3對，H-03改群數後從舊制84對降到39對）
互補程度分布：低31對／中8對／高0對
```

**自動化掃描**：對全部31對「低互補」的說明文字做關鍵字掃描（「不會帶來分散」「不能宣稱」等），**31/31（100%）都有明確揭露**，無一遺漏。

### 3.3 cluster_identity（H-08，單群身份）

**額外的專屬鐵則**：禁止推論「這群適合什麼總經環境」——那是S-01/S-02決策層的工作，這裡完全沒給任何總經資訊，推論了就是編造，還會污染後面決策層要用的素材。

**實證稽核**：16群（TW6/US7/XM3）全部完成。自動化掃描「升息/降息/通膨環境/景氣循環/適合在」等總經推論字眼，**16群、0命中**。

**S-01 開發時額外發現的重要限制**：cluster_identity 的四個輸出欄位（identity_label/mechanism_note/performance_pattern/caveat）是同一次呼叫、共用含真實年份的上下文產生的。實測 `performance_pattern` 16/16、`caveat` 14/16 都含有日曆年份字串，只有 `identity_label`／`mechanism_note` 沒有外洩——**但這只是這次沒外洩，不是架構保證**。這正是「架構排除、不靠信任」這條總原則的具體案例：S-01 因此定案決策層介面只收 `identity_label`。

### 3.4 decision_layer_arms B_llm（S-05，總經決策層）

**額外的專屬鐵則**：①看不到具體日期，不可假裝知道現在是哪一年、發生過什麼歷史事件②優先參考「條件式」績效，不能只看群的整體特徵而忽略總經狀態③若各群條件式表現差異不大，要在caveat裡明講，不可硬掰出不存在的偏好。

**實證稽核**：人工核對2組真實情境（XM_normal/復甦、US_normal/過熱）的完整rationale/caveat文字，確認：只引用提供的數字、正確做條件式比較排名、對被排除的群給出具體理由、差距不大時誠實承認判斷帶有主觀性。**S-07（重複執行穩定度）額外提供了一個間接但有力的證據**：三個測試情境、共15次獨立呼叫，純規則基準的選擇 **100%** 都被LLM決策包含在內——代表LLM的判斷穩定錨定在程式算好的客觀數字上，沒有偏離到自己編故事的方向。

## 4. 跨節點共用的基礎設施

- **H-23 額度煞車**（`utils/openai_quota.py`）：呼叫前檢查今日免費額度，額度不足直接擋下、不會靜默改用付費模型。這不是抗幻覺本身，但是同一種「架構排除、不事後信任」哲學在成本控制上的體現。
- **`--dry-run`／`--resume`**：三個已上線節點（cluster_story/cluster_identity/decision層）都支援先印prompt不花錢確認、額度暫停後接續執行不用整批重來。
- **raw_verdict/raw_evidence 可回驗機制**（T10設計，尚未上線但架構已定）：LLM 產出的文字連同它所依據的原始判決一起保存，供事後人工核對文字有沒有跟凍結數字矛盾。

## 6. 已知限制（誠實揭露，供論文寫作）

- **T10 尚未有真實資料稽核**——架構設計完成、合成資料測試通過，但沒有真實呼叫紀錄，不能跟其他三個節點的實證數字並列宣稱「全部節點皆已驗證」。
- **稽核方式是自動化關鍵字掃描＋抽樣人工核對，不是逐字全文人工審閱全部39對＋16群＋多次決策呼叫的所有輸出**——關鍵字掃描能抓到「明顯違規」，但無法排除更隱晦的幻覈（例如語氣正確但引用數字對不準原始側寫）。若要更嚴謹，需要抽樣做「文字內容 vs 原始side-by-side數字」的逐項比對，目前只做了少量案例的人工核對。
- **decision_layer_arms 的品質驗證只涵蓋3個情境、15次呼叫**——樣本量還小，且是靜態單一快照，不是涵蓋各種總經狀態組合的完整驗證。
- **S-06（Prompt風格穩健度）已定案暫緩**——不知道換一種問法、換一種資訊呈現方式，這套抗幻覺設計還撐不撐得住。
- **模型換過一次**（terra/sol → gpt-5/gpt-5-mini，H-24），現有稽核數字都是gpt-5的結果；若之後又換模型，這裡的稽核結論不會自動適用，需要重新驗證。

## 7. 對論文的意義

呼應老師說的「方法論可泛化」：這套「程式判決凍結＋結構化輸出＋只給必要資訊」的設計，不綁定任何特定的LLM節點——同一套原則被獨立套用在四個完全不同的任務（轉譯、雙群比較、單群描述、總經決策）上，且每次遇到新任務都會多加一條該任務專屬的鐵則（低互補要明講/不可推論總經/看不到日期），顯示這是一個**可以延伸到新任務的設計模式**，不是為了單一功能量身訂做、換個場景就失效的做法。
