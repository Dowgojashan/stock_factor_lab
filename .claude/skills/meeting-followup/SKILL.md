# 開會前自我稽核：有沒有默默漏掉的事

> 跟 `meeting-prep` 的差別：`meeting-prep` 是「整理要報告什麼」，
> 這個是「找出**沒做但應該做**、以及**做了但文件沒更新**的東西」。通常先跑這個，再跑 prep。

## 為什麼需要

實際發生過的兩種漏失：

1. **文件沒跟著更新**：2026-09-02 老師終止總經方向，`v10 §10` 過了 5 天才訂正，
   而 `CLAUDE.md` 更是到 09-09 才發現還在寫「H-18③/H-20/H-21 未完成」——三份文件互相抄，
   錯誤說法輾轉傳了一週。
2. **規劃了但沒執行**：`H-26d` 是 `落差處理方案_v1.md` 落差 3 規劃的「方案 E」，
   常數 `HRP_ROBUSTNESS_WINDOW_TW` 留在程式裡卻**從未被引用執行過**，
   靠 code review 全域搜尋才發現。

## 檢查清單

### 1. 老師交代的事，逐項對狀態

打開上次會議的整理結果，每一項標：完成／進行中／卡住／判斷後不做。
**「判斷後不做」一定要有記錄的理由**，而且要在會議上主動說明，不能默默跳過。

### 2. 追蹤文件的 ☐ 有沒有變 ☑

```bash
grep -n "☐" 文件/開發待辦追蹤.md 文件/應用層開發追蹤.md
```

還是 ☐ 的項目：是真的還沒做，還是做完忘了更新狀態？

### 3. 🔴 做完的事，文件有沒有同步

對每一項「已完成」，確認這些地方都反映了：

| 文件 | 要確認什麼 |
|---|---|
| `文件/研究框架總覽_v10.md` | 結果數字、章節骨架、§10 尚未完成項目 |
| `文件/現況銜接.md` | 現況、下一步、已決定不做的事 |
| `CLAUDE.md` | 第 2 節進度摘要（測試數、階段狀態）|
| 對應的追蹤文件 | 狀態欄與完成日期 |

### 4. 規劃了但沒執行的殘留

找出「文件說要做但程式裡沒有」的項目：

```bash
# 例：文件提到某個常數/函式，但全域搜尋零引用 = 規劃了沒執行
grep -rn "<常數或函式名>" code/ --include="*.py" | grep -v "_archive"
```

### 5. 數字有沒有過期

文件裡的關鍵數字要能對回來源檔。已知踩過的雷：

| 數字 | 權威來源 |
|---|---|
| 候選池 15,810（TW 7,128／US 8,682）| `_frozen/stage0/candidate_index.parquet` |
| 基準 CAGR：TW 8.4256%／US 11.0556% | `code/research/contracts.py` 的 `BENCHMARK_CAGR` |
| HRP 群數 TW 6／US 7／XM 3 | `_frozen/stage3/`（H-03 輪廓係數決定）|
| 測試項數 131 | `cd code && python -m research.tests` 實跑 |
| walk-forward 各格結果 | `_analysis_outputs_robustness/walkforward_matrix_detail.csv` |
| 封存區容量 | 實測 `du -sh`，**不要抄 `.gitignore` 註解**（已知過期：註解寫 58.5GB，實測 189GB）|

### 6. 產出

在對話框列出：**漏掉的事**、**文件不一致處**、**過期數字**三類，
每項附證據（檔案:行號或指令輸出）。不要只說「有問題」，要能指出在哪。
