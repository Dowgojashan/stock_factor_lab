# 開會後：逐字稿 → 可執行待辦

## 為什麼要照流程走

這個專案吃過虧：**2026-09-02 老師會議終止了總經方向（方向 C），但 `研究框架總覽_v10.md` §10
沒有跟著更新，過時了整整 5 天**，直到 09-07 才發現並訂正。當時只更新了 `開發待辦追蹤.md`，
沒有回頭掃「還有哪些文件在講舊路線」。第 4 步就是為了防這件事。

## 步驟

### 1. 取得逐字稿內容

PDF 一律用 `fitz` 抓文字——這台機器沒裝 `pdftoppm`，`Read` 工具渲染 PDF 頁面會失敗：

```bash
python -c "import fitz; d=fitz.open('9-8咪挺.pdf'); print('\n'.join(p.get_text() for p in d))"
```

⚠️ 逐字稿是老師談話內容，**不對外公開**（`.gitignore` 已排除 `*咪挺*`／`*逐字稿*`）。
不要把內容貼進會進版本庫的文件，只摘要與引用必要的關鍵句。

### 2. 抽出老師的「原話」，不要改寫

**關鍵指示一律逐字保留**，這是這個專案的既有慣例，因為事後判斷「老師到底要不要我做這件事」
全靠原話。範例（`開發待辦追蹤.md` 的寫法）：

> ❌ **方向 C（總經→選群）確定不做**——「看起來都跟總經沒關係⋯**不會有答案，不會有好答案**」

改寫成自己的話會流失語氣強度，之後就會出現「老師到底是建議還是要求」的爭議。

### 3. 分成四類（處理方式完全不同）

| 類別 | 判準 | 處理 |
|---|---|---|
| **必做** | 老師明確要求、給了時程 | 建實驗 ID（H-xx／M-xx／S-xx），寫進追蹤文件待辦 |
| **取消** | 老師說不做了 | 🔴 最需要小心，見第 4 步 |
| **待確認** | 老師語意模糊、或需要你先做才知道 | 記進「下次會議要問」清單 |
| **感想／背景** | 老師的觀察、產業經驗、閒聊 | 記錄但不轉成待辦，不要過度解讀成指示 |

⚠️ 不要把「感想」當成「必做」。老師講很多背景脈絡，硬要每句都變成任務會做白工。

### 4. 🔴 檢查推翻了哪些既有共識（最容易漏，也最痛）

只要有「取消」或「方向改變」類的項目，**必須**回頭掃這些地方有沒有還在講舊路線：

- `文件/研究框架總覽_v10.md`（尤其論文章節骨架、§10 尚未完成項目）
- `文件/開發待辦追蹤.md`、`文件/應用層開發追蹤.md`
- `文件/現況銜接.md`（§4「已決定不做的事」要加一筆）
- `CLAUDE.md`（第 2 節的進度摘要）

用關鍵字搜尋被取消的主題，逐一確認。**沒做這步的話，過時說法會繼續在文件間傳播**
（CLAUDE.md 的「H-18③/H-20/H-21 未完成」就是這樣輾轉傳了好幾天）。

### 5. 產出

- 更新對應的追蹤文件（研究部 → `開發待辦追蹤.md`；應用層 → `應用層開發追蹤.md`）
- 「待確認」項目彙整成／併入下次會議的待報告文件
- 在 `文件/現況銜接.md` 更新現況與「已決定不做的事」
- 每一項都標**日期**與**出處**（哪次會議）

### 6. 回報

直接在對話框說明整理結果（使用者不喜歡自動產生額外的報告文件），
並列出「這次推翻了什麼」讓使用者確認。
