# 論文結果章節的寫作流程

寫作 session 負責論文；實驗、重跑、新的統計計算一律交給實驗 session（名稱會變，用 ListAgents 確認，2026-11 是 `stock-factor-lab-bf`）。
**寫什麼、怎麼寫**（第四章章首、各節的開頭五步與結尾兩步、三層結構與「討論」小節、證據性質、事後追加的標示）見 `thesis-narrative-review` 第 3、12、53–56、62 條；這裡只講**工作流程**。

## 一、動筆前：盤點

1. **讀設計與待寫註記。** 先讀第三章對應的設計小節、第三章表「設計項目與待檢驗內容的對照」的該列，以及第四章該節的 `\pending{}` 註記與章首驗證路線表的該列，列出承諾要檢驗的每一項（例如「虛無模型」「逐年報酬」「合併方式的比較」）與對照組。寫完後逐項打勾，缺的就是要補的。
2. **列出結果檔並確認時間。** 依 CLAUDE.md 規則 0，比對每個結果檔的產生時間與上游最後一次重跑的時間（`ls -la --time-style=+%Y-%m-%d_%H:%M`，或 manifest 的 produced_at）。比上游舊的就是過期。同一組結果有多個版本時（實例：美股權重規則有加流動性門檻前、後兩版），先確認哪一版是現行、哪一版要並列，並讀產生程式確認指標的算法（實例：實戰層的夏普比率是日報酬 ×√252，不是月報酬）。
3. **盤點既有的圖。** 搜尋 `_analysis_outputs_*`、`_analysis_outputs_robustness/figures/`、`_analysis_outputs_atlas/`、`_frozen/` 底下的 png，逐一判斷：
   - 時間是否早於上游重跑（實例：台股第一階段曲線圖還畫著股價修正前的 8.43% 基準；圖鑑與第三階段增益圖是舊池）；
   - 內容屬於哪一節（實例：群數隨窗口變化的圖屬於 4-4，不是 4-3）；
   - 是否已被其他表格取代，不需要了。
   回報使用者時，用表格列出「圖檔 × 時間 × 需不需要 × 理由」。

## 二、與實驗 session 的分工

4. **過期的圖或結果，請實驗 session 重跑；寫作 session 不自己重跑。** 訊息裡要寫明：
   - 使用者授權的原話；
   - 覆蓋前先備份；
   - 只用唯讀計算，不燒 LLM 額度，不動凍結檔；
   - **先估時間，預計超過 30 分鐘就先停下來回報**（實例：圖鑑重畫跑了 68 分鐘，事前沒估）；
   - 完成後回覆給寫作 session，附檔案路徑與時間。
5. **寫作 session 可以做、與不可以做的計算。**
   - 可以：從既有結果檔做簡單的彙整與畫圖，例如分組中位數、比例、逐年報酬、既有欄位的排名相關、把數字整理成表。這類計算若是看過主結果才做的，正文標「（事後追加）」。
   - 不可以：新的統計模型、迴歸、重建分群、重跑任何主鏈模組。這些都交給實驗 session。
6. **實驗 session 臨時重算的數字，先存成正式結果檔才引用。** 請對方把腳本移進 `code/research/`、輸出放進結果目錄並附 manifest。論文原始碼在該段落後加一行 `%` 註解，寫明來源檔與日期。
7. **對方回報的結果，先讀他的腳本確認做法正確，再採用。** 他給的數字，也要用結果檔再核對一次。

## 三、畫圖

8. **論文的圖一律用現行結果檔重畫，不直接放實驗 session 的 png。** 那些圖帶有內部代號（openSec\_boost、Phase、4-20），標題與標籤不合論文格式。重畫後，拿實驗 session 重跑的數字交叉核對。
9. **檔案與程式。** 資料圖輸出 `論文/figures/fig_res_*.pdf`，畫圖程式存成 `論文/figures/make_*.py`，開頭註明資料來源檔與日期，資料更新後可直接重跑；另存一份 png 到 scratchpad，用來目視檢查。示意圖（流程、架構、驗證層次）用 TikZ 寫成 `論文/figures/fig_*.tex`，以 `\resizebox{\textwidth}{!}{\input{...}}` 插入，樣式沿用 `fig_elite_flow.tex`。
10. **格式。**
    - matplotlib 字型 `['Arial', 'Microsoft JhengHei']`，`pdf.fonttype = 42`，`axes.unicode_minus = False`；
    - 標籤用中文與讀者看得懂的名稱，不用內部代號；
    - 分類配色依序用 `#2a78d6`、`#eb6834`、`#1baf7a`、`#eda100`、`#e87ba4`（dataviz 的預設色盤），並搭配不同的標記形狀，黑白列印也能分辨；
    - 單一方向的數量用藍色單色色階（相鄰色階要拉開，實例：資金比例五階一度太接近）；正負值（報酬）用紅—灰—藍雙色色階，並在圖說寫明顏色的意義；
    - 極端值截斷色階，避免其他格被壓淡（實例：台股 2009 年 +340%）；
    - 每格標數字時，接近 0 的值改標一位小數，避免看成 0；
    - 圖例不可蓋住資料，必要時移到圖外；
    - TikZ 圖中的節號用 `\mbox{\ref{...}}` 包起來，避免「4-4」在連字號處斷行；文字框要留足寬度與列距，以免框線重疊。
11. **畫完一定要渲染出來看。** 檢查標籤重疊、圖例位置、空白過多、文字是否超出框線。必要時用 `bbox_inches='tight'` 裁邊。

## 四、表格

12. **表格的數字用程式直接從結果檔產生**，印出 LaTeX 列後貼入，不要手抄。產生表格的程式存成 `論文/figures/make_tab*.py`（實例：`make_tab45.py`），同時印出正文引用的彙整數字，供日後核對。正文寫的範圍要和表格逐一對照（實例：手抄出現 17.5／17.4、−0.24／−0.23 的四捨五入錯誤）。
13. **表格放不進同一頁時，先縮短**：依類型彙整、依市場分組以縮短名稱欄、把細節移到附錄，或改用圖呈現。欄位太寬時，改用 `\footnotesize`、縮小 `\tabcolsep`、縮短欄位標題（例如「2015--23」）。

## 五、撰寫、插入論文與編譯

14. **依固定格式撰寫。** 第四章各節的開頭一段依「開頭五步」、結尾一段依「結尾兩步」（`thesis-narrative-review` 第 54 條）；回答研究問題的節，節末另立「討論」小節（第 55 條）。
15. **修改前先備份**到 `論文/chapters/_backup/`，檔名加日期與用途，例如 `ch04_validation_20261122_before_43.tex`。
16. **用 Python 腳本修改 .tex。** 先把 CRLF 正規化為 LF，每個替換都 `assert` 只出現一次，寫回時再還原 CRLF（`.gitignore` 等檔案也可能是 CRLF）。**腳本用 Write 工具寫成 scratchpad 裡的 .py 檔再執行**，不要用 bash heredoc：heredoc 會把 `\\` 吃成 `\`，使正規表示式出錯或 `\a`、`\t` 變成控制字元（2026-11-23、11-24 實測）。腳本內的反斜線用 `B = "\\"` 拼接；正規表示式用 `re.escape`。長段落先寫成獨立的 .tex 檔，再由腳本以佔位符插入。
17. **圖表的原始碼放在該小節文字之後**；一節有多個圖表時，集中放在節尾。
18. **編譯**（在 `論文/` 下執行；引用有變才跑 biber）：預設分兩步，先跑兩、三次
    `powershell -NoProfile -Command "$env:PATH=\"$env:LOCALAPPDATA\Programs\MiKTeX\miktex\bin\x64;$env:PATH\"; xelatex -interaction=nonstopmode -no-pdf main.tex"`
    再執行 `xdvipdfmx main.xdv`。直接讓 xelatex 輸出 PDF 偶發 `dvipdfmx:fatal: File ended prematurely`，重編常常仍然失敗。
    - 出現 `File ended while scanning`，代表輔助檔被截斷：刪掉 `main.aux`、`main.toc`、`main.out`、`main.lof`、`main.lot` 後重編三次；
    - 新增圖表或節之後，交叉參照要跑三次才會穩定；
    - 小型表格被集中到「只放表格的一頁」、夾在段落中間時，把該表的位置參數改成 `[!htb]`，禁止它單獨成頁。
19. **編譯後檢查三件事**：
    - 沒有 undefined reference；
    - 沒有新的 overfull 警告（處理方式見 `thesis-narrative-review` 第 69 條）；
    - **渲染該節的頁面實際看版面**：圖表有沒有夾在段落中間、有沒有單獨佔一頁或留下大片空白、有沒有跨到下一節。頁數多時拼成縮圖總覽，但有疑問的頁面要放大確認，縮圖的排列可能讓人誤判。

## 六、寫完一節的自檢

20. **把每段第一句依序抄出來讀一遍**：只讀第一句就要知道這段的重點（`thesis-narrative-review` 第 3 條）；只做預告、說法模糊、一開頭就是數字、結論藏在中段的，都要改寫。
21. **掃描口語用詞**（`thesis-narrative-review` 第 40 條的對照表），改成專業用語。
22. **第四章的格式核對**：開頭五步與結尾兩步是否齊全（第 54 條）；判讀原則是否只在章首說過一次，後文改寫「（見本章章首）」（第 13 條）；事後追加的分析是否都標了「（事後追加）」（第 62 條）；本節是否已列在章首的驗證路線表中，表中的主張與對照組是否與正文一致；第四章新增的比較，是否已回頭補進第三章的對照表（第 59 條）。

## 七、回報

23. **回報使用者時，依序交代**：改了什麼（按小節）、新增的圖表與資料來源和日期、與實驗 session 交辦了什麼、哪些還在等回覆、哪些需要使用者決定。改前的備份檔名也要附上。
